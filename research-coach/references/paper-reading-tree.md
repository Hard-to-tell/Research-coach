# 论文解析树：把读论文变成回答问题

每读一篇论文，按下面的树逐项填。填不出来的地方，就是没读懂的地方。

## 摘要 (Abstract)
- 任务 (Task)
- 前人方法的技术挑战（围绕本文解决的那个挑战）
- 一句话说解决挑战的关键见解 (insight) / 动机
  - insight 是比较通用的高层思想，和具体的技术贡献不是一回事
- 技术贡献 1：一句话说做法，一句话说好处
- 技术贡献 2：同上
- 实验结论

## 引言 (Introduction)
- 任务和应用
- 前人方法的技术挑战
  - 挑战 1：前人方法 → 失败案例（局限） → 技术原因
  - 挑战 2：前人方法 → 失败案例（局限） → 技术原因
- 本文解决挑战的 pipeline
  - 一句话说核心创新 / 见解 / 贡献
  - 贡献 1：具体怎么做 + 优势 / 见解
  - 贡献 2：为了解决什么问题 + 具体怎么做 + 优势 / 见解
- 亮眼的 demo / 应用

## 方法 (Method)
- 概览：具体任务、输入、输出；方法的第一步、第二步、第三步
- 每个 pipeline 模块：动机 / 做法 / 为什么能 work / 技术优势

## 实验 (Experiments)
- 对比实验：和哪些 baseline 比，用什么指标，在什么数据上
- 消融实验：
  - 核心贡献和重要组件，分别对性能有多大影响
  - 每个模块里的设计选择，分别对性能有多大影响

## 读完后补一行
- 这篇在我的时间轴上是**里程碑**还是 **follow-up**？依据是什么？
- 它留下了什么没解决的问题？我能不能接着做？
