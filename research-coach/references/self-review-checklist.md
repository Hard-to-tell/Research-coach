# 论文自我评审清单

投稿前站在审稿人的角度，逐条打勾。任何一条答"是"，都要写下补救办法。

## 1. 技术贡献够不够
- [ ] 要解决的失败案例其实很常见，或者别人早就知道？
- [ ] 用的技术已经被研究透了，带来的提升是可以预见的？

## 2. 写得清不清楚
- [ ] 引言没有清楚说出贡献？
- [ ] pipeline 图没有讲清楚流程和技术贡献？
- [ ] 缺技术细节，别人没法复现？
- [ ] 有方法模块没写设计动机？

## 3. 效果够不够好
- [ ] 没有比之前的方法好很多？
- [ ] 结果不够让人眼前一亮？

## 4. 实验够不够充分
- [ ] 缺消融实验？
- [ ] 缺重要的 baseline 或评测指标？
- [ ] 数据太简单，证明不了方法真的有效？

## 5. 方法设计合不合理
- [ ] 实验设置不现实？
- [ ] 方法有明显的技术缺陷，看起来不合理？
- [ ] 不够鲁棒，每个场景都要单独调超参？
- [ ] 带来好处的同时引入了更大的局限，整体得不偿失？
